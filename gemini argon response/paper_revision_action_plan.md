# Paper Revision & Codebase Audit Plan: Graph Digital Twin for Smart Grid Cyber-Resilience

## 1. Executive Summary of Codebase Audit

Your experimental suite covers the essential pillars required for an IEEE Transactions or top-tier conference submission:

* **Baseline & Architecture Comparison (`compare_models.py`):** Evaluates Flat MLP, Isotropic GCN, Multi-Head GAT, and the proposed GraphSAGE model under a unified multi-task loss ($L_{\text{total}} = L_{\text{graph}} + 1.5 L_{\text{node}}$).

* **Cross-Grid Scalability & Transfer Learning (`evaluate_ieee30.py`):** Tests inductive zero-shot generalization, few-shot transfer learning ($N=200$), and training from scratch on the larger IEEE 30-bus system with dynamic line/generator outages and multi-target attacks.

* **Sensitivity & Robustness (`evaluate_robustness.py`):** Sweeps across measurement noise ($\sigma \in [0.01, 0.15]$) and attack magnitudes ($1.1\times$ to $2.0\times$ load scaling).

* **Topological Reconfiguration (`evaluate_topology_generalization.py`):** Demonstrates the critical flaw of flat MLPs versus GNNs under $N-1$ non-bridge transmission line outages.

* **Classical Bad Data Detection / WLS Comparison (`evaluate_wls.py`):** Compares Weighted Least Squares (WLS) state estimation against the Graph Digital Twin (GDT) state reconstruction on Bus 5.

* **Explainable AI (`smart_grid_digital_twin.ipynb`):** Implements 50-step Integrated Gradients (IG) to attribute anomaly scores to specific buses and physical measurements ($V_m, \theta, P, Q$).

## 2. Critical Code & Methodology Discrepancies (Fix Before Submission)

### Issue A: Unused Edge Attributes (`edge_attr`) in GNN Layers

* **The Discrepancy:** In `evaluate_ieee30.py`, `evaluate_topology_generalization.py`, and the notebook, you carefully compute and normalize physical branch impedance features—resistance $R$ and reactance $X$ (`edge_attr_norm`). However, `SAGEConv` and `GCNConv` in PyTorch Geometric **do not accept `edge_attr`** in their `forward(x, edge_index)` passes, and your `GATModel` does not pass `edge_attr` into `GATConv`.

* **Reviewer Risk:** If your manuscript claims that the GNN incorporates physical line impedances ($R, X$) during message passing, reviewers checking the code will flag a mismatch.

* **The Fix:**

  1. *Option 1 (Text Alignment):* Clarify in the paper that line impedances $(R, X)$ govern the underlying AC power flow equations ($Y_{\text{bus}}$ matrix) during state generation, while the GNN operates purely on the active topological adjacency matrix $\mathcal{A}$ and node states $X \in \mathbb{R}^{N \times 4}$.

  2. *Option 2 (Code Upgrade):* Replace `SAGEConv` with `GINEConv` or a custom `MessagePassing` layer that concatenates `edge_attr` into neighbor messages: $\mathbf{m}_{uv} = \text{MLP}(\mathbf{h}_u \parallel \mathbf{h}_v \parallel \mathbf{e}_{uv})$.

### Issue B: Simulated vs. Actual Model Output in `evaluate_wls.py`

* **The Discrepancy:** In `evaluate_wls.py` (Lines 107–112), the GDT mitigated voltage estimate `gdt_v_est` is generated by taking the ground-truth `compromised_buses` list and adding synthetic Gaussian noise $\mathcal{N}(0, 0.002)$ to `nominal_v[bus]`, rather than running inference with your trained `SAGEModel` to dynamically predict which buses are compromised.

* **Reviewer Risk:** Hardcoding the localized buses in the WLS comparison script disconnects the state mitigation metric from the actual GNN localization accuracy.

* **The Fix:** Load `checkpoints/compare_graphsage_proposed.pt` inside `evaluate_wls.py`, pass the normalized attacked state tensor into `model(x, edge_index)`, use `node_preds = torch.argmax(node_logits, dim=-1)` to identify flagged buses, and replace only those *model-predicted* buses with the forecasted nominal baseline before computing MSE.

### Issue C: Data Leakage in Normalization (`evaluate_ieee30.py` & Notebook)

* **The Discrepancy:** In `evaluate_ieee30.py` (Lines 191–197) and `smart_grid_digital_twin.ipynb`, `feat_mean` and `feat_std` are computed across **all** generated samples (`all_features`) *before* calling `random_split` into train, validation, and test sets. Furthermore, in `evaluate_ieee30.py`, `all_features` includes the 50% attacked samples, which shifts the mean and standard deviation away from nominal operating statistics.

* **The Fix:** Compute `feat_mean` and `feat_std` strictly on the **training split** (or strictly on benign historical baseline samples) and apply those parameters to normalize the validation and test splits.

### Issue D: Comment vs. Code Mismatch & Missing `device` Definition in `evaluate_ieee30.py`

* **Bug 1 (NameError):** In `evaluate_ieee30.py`, `device` is used on Line 231 (`to(device)`), but `device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')` is never defined inside `main()`! Running `evaluate_ieee30.py` standalone will throw a `NameError: name 'device' is not defined`.

* **Bug 2 (Sample Count):** Section comments on Lines 241 and 272 state `(FINE-TUNING ON 50 SAMPLES)`, whereas `train_size = 200` on Line 214 and the plot title correctly state `200 Training Samples`.

* **Bug 3 (Hardcoded Path):** Line 23 has `sys.path.append(r"c:\Users\Himanshu\Documents\Smart Grid")`. Replace this with dynamic path resolution (`os.path.dirname(os.path.abspath(__file__))`) for clean reproducibility on Linux/Colab.

### Issue E: Loss Weighting & Hidden Dimension Inconsistency Across Scripts

* **The Discrepancy:**

  * `compare_models.py` and `evaluate_ieee30.py` use `hidden_channels=64` and a multi-task loss weight of $\lambda = 1.5$ (`loss = loss_graph + 1.5 * loss_node`).

  * `smart_grid_digital_twin.ipynb` uses `hidden_channels=32` and $\lambda = 1.0$ (`loss = loss_graph + 1.0 * loss_node`).

  * `evaluate_robustness.py` imports `SmartGridGNN` from `src/model.py` and loads `checkpoints/best_model.pt`, whereas `evaluate_topology_generalization.py` imports `SAGEModel` from `compare_models.py` and loads `checkpoints/compare_graphsage_proposed.pt`.

* **The Fix:** Standardize all scripts and the paper text to `hidden_channels=64` and $\lambda = 1.5$.

### Patch 2: Upgrade `evaluate_wls.py` to Use Live GNN Localization + Chi-Square ($\chi^2$) BDD Metric

Reviewers in power systems always ask whether the simulated FDIA actually bypasses the standard **Largest Normalized Residual (LNR)** or **Chi-Square (**$\chi^2$**) Bad Data Detector (BDD)**. Adding the $\chi^2$ residual check to `evaluate_wls.py` proves mathematically that your AC-power-flow-consistent attack is stealthy to WLS.

Add this block right after `ppe.estimate(net_est, init="flat")` in `evaluate_wls.py`:

```
    # Compute WLS Objective / Chi-Square Bad Data Detection Residual J(x)
    # Degrees of freedom: m (measurements) - (2N - 1) (state variables)
    m_meas = len(net_est.measurement)
    n_states = 2 * len(net_est.bus) - 1
    dof = m_meas - n_states
    
    # Extract WLS residuals between measured and estimated values
    v_meas_vals = net_est.measurement[net_est.measurement.measurement_type == 'v']['value'].values
    v_est_vals = net_est.res_bus_est.vm_pu.values
    J_residual_v = np.sum(((v_meas_vals - v_est_vals) / std_v) ** 2)
    print(f"WLS Voltage Residual J(x): {J_residual_v:.2f} (DoF = {dof})")

```
